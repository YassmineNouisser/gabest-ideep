1. Contexte du projet

GaBest est une plateforme full-stack d'économie circulaire et de protection environnementale ciblant la région de Gabès (Tunisie), caractérisée par une forte activité industrielle (phosphates, cimenterie, centrale thermique, port) et des enjeux sanitaires majeurs liés à la pollution atmosphérique et hydrique.

Parties prenantes

AgriculteursCultures maraîchères, olives, dattes. Reçoivent alertes pollution, diagnostics maladies, valorisation des déchets, recommandations eau/sol.
IndustrielsPhosphates, cimenterie, énergie, port. Optimisent leur production selon le vent et valorisent leurs sous-produits.
RecycleursGèrent flux entrants pré-caractérisés, routage flotte, partenariats symbiotiques (Shapley).
MédecinsSuivent en temps réel les signalements patients et les zones critiques IA.
Autorités publiquesCompliance environnementale, pilotage politique d'économie circulaire.

Objectifs

  • Anticiper les pics de pollution à 48 h sur 8 quartiers
  • Réduire les pertes agricoles (maladies, mauvaise irrigation, sols dégradés)
  • Transformer les déchets agricoles et industriels en revenus et énergie
  • Protéger la santé publique via un dashboard médical temps réel
  • Proposer un modèle scalable à l'échelle nationale tunisienne

2. Architecture générale & stack technique

Vue d'ensemble

Architecture 3-tiers : Frontend React (SPA) ↔ Backend FastAPI (inférence IA) ↔ Supabase (PostgreSQL + Realtime) + OpenWeatherMap (API externe).

Stack technique

Couche Technologies
Frontend React 18.3 · React Router 7.13 · TypeScript · Vite 6.3 · Tailwind CSS 4.1 · Radix UI (29 primitives) · Material-UI 7.3 · Recharts · Leaflet + React-Leaflet · Motion · Lucide · React Hook Form · Sonner
Backend FastAPI · Uvicorn · PyTorch 2.2 · TorchVision · TorchGeometric 2.5 · scikit-learn 1.4 · XGBoost 2.0 · Pandas · NumPy · Pillow · Captum · SHAP
Base de données Supabase (PostgreSQL) · Row-Level Security · Realtime (WebSocket)
APIs externes OpenWeatherMap (pollution atmosphérique + météo) · OpenAI (prévu)
Outils dev Vite HMR · ESBuild · PostCSS · Git · npm / pnpm

Flux de données

  1. Collecte : capteurs simulés + signalements patients Supabase + OpenWeatherMap polling
  2. Inférence : FastAPI charge les modèles au lifespan (warm boot) et expose 12+ endpoints REST
  3. Diffusion : frontend React consomme les APIs + s'abonne au Realtime Supabase
  4. Action : utilisateur reçoit alertes, recommandations, matching, XAI

4. Fonctionnalités IA · 8 modèles embarqués

Diversité des approches : 1 Graph Neural Network · 1 CNN (ResNet-50) · 1 Random Forest · 5 XGBoost. Tous les modèles sont explicables (SHAP, Grad-CAM, Captum, attention GAT).

4.1 GaBest · Prédiction de zones critiques de pollution

GNN + LSTM PyTorch Geometric XAI : GAT + SHAP + Captum GET /predict

Entrée : 8 quartiers × 7 jours historiques (SO₂, PM2.5, PM10, NO₂, vent, humidité, signalements citoyens).

Sortie : classification 4 classes (Normal · Vigilance · Critique · Urgence) par quartier, avec score de confiance.

Explicabilité : poids d'attention GAT (influence des quartiers voisins) + SHAP KernelExplainer + Captum Integrated Gradients (attribution temporelle par jour).

Artefact : gabest_best.pt (989 KB) · Scaler : scaler.pkl · Dataset : signalements_gabes.csv (2023-01-01 → 2024-12-31).

4.2 GabesHeal F2 · Diagnostic des maladies des cultures

ResNet-50 fine-tuné PyTorch + TorchVision XAI : Grad-CAM POST /predict-disease

Entrée : photo de feuille (JPEG, redimensionnée 224×224).

Sortie : maladie + nom de plante en français + top-3 candidats + sévérité + traitement (produit + dosage + prix TND) + bbox + overlay Grad-CAM.

Classes : 38 classes PlantVillage (pomme, maïs, vigne, tomate, pomme de terre…).

Artefact : gabeseal_f2_model.pth (98.6 MB).

4.3 WindShield · Optimisation de production selon le vent

Random Forest + modèle économique POST /wind/predict POST /wind/monthly-report

Entrée : métadonnées usine (lat/lon, % production actuelle) + météo live (direction et vitesse du vent, température).

Sortie : score de risque (faible/moyen/élevé), classification direction vent, prévision panache (grille lat/lon/z), ajustement production (-20 % à +30 %), économies estimées (DT).

Modèle économique : amendes ANPE évitées + économies santé + crédits carbone + coûts produit, agrégés en rapport mensuel jour par jour.

Artefact : invisible_shield_models.pkl.

4.4 GypsiFert · Dosage phosphogypse en amendement agricole

3× XGBoost XAI : SHAP POST /gypsifert/predict

Entrée : pH, Ca, Mg, CEC, Cd, Pb, pluviométrie, type de sol, culture visée, surface (ha).

Sortie : dosage optimal (t/ha), gain de rendement (%), score de contamination, feature importance SHAP.

Artefacts : model_dosage.pkl, model_gain.pkl, model_risk.pkl + scaler + explainer.

4.5 BioMatch · Valorisation énergétique des déchets agricoles

XGBoost (prédiction HHV) POST /api/farmer/estimate GET /api/waste-types

Entrée : type de déchet (10 types : luzerne, grignons d'olive, noyaux de dattes, paille de blé…), quantité (t), humidité (%).

Sortie : pouvoir calorifique supérieur HHV (MJ/kg), énergie contenue (MWh), qualité (premium/standard/low), valeur marché (DT).

Matching : 7 usines (cimenterie, biomasse, biogaz, biocarburant, compost) avec contraintes (PCI min, tonnage, acceptation) + 5 recycleurs spécialisés.

4.6 WaterShield · Qualité de l'eau d'irrigation

6× XGBoost POST /watershield/predict

Entrée : source (puits, oasis, canal, surface), distance à GCT (km), indices visuels (couleur, odeur), pluviométrie, saison.

Sortie : score de sécurité (0–100), bande (sûre · à surveiller · dégradée · critique), 4 probabilités de contaminants (salinité, pH anormal, métaux lourds, turbidité), cultures compatibles, recommandation (traiter / diluer / changer de source), chimie imputée.

Artefacts : 6 modèles XGBoost + feature_names + config.

4.7 PhosphoMatch · Matching lots phosphogypse → acheteurs

Scoring sous contraintes Frontend (lib/phosphomatch.ts)

Entrée : caractéristiques du lot (pureté, fluor, P₂O₅, humidité, métaux lourds, radioactivité, quantité).

Sortie : liste d'acheteurs classés (cimenterie, plâtre, engrais, BTP, recyclage) avec score de compatibilité selon contraintes max autorisées par acheteur.

Tiers qualité : standard, haute-pureté, bas-grade (presets).

4.8 IndustryMatch · Routage déchets industriels → acheteurs agronomes

Scoring heuristique XAI via GypsiFert (SHAP)

Entrée : 8 types de déchets industriels (phosphogypse, boues organiques, cendres volantes, laitier, HDPE, eaux de lavage, poussière de gypse, résidus de chaux), quantité, zone, pureté.

Sortie : acheteurs (agriculteurs, cimenterie, plâtrerie, BTP, compost, engrais) avec distance, revenu estimé, CO₂ évité, attribution SHAP pour le risque agronomique.

5. Architecture des données & intégrations

5.1 Schéma Supabase

Table public.patients pour les signalements médicaux et l'exposition à la pollution :

  • id, created_at, prenom, age, zone
  • symptomes (array), duree, profil (array)
  • pollution (JSONB : SO₂, PM2.5, PM10, NO₂, AQI)
  • rapport (JSONB : analyse IA + recommandations)

Realtime activé pour le dashboard médecin · RLS pour accès anonyme contrôlé.

Synthèse

GaBest est une plateforme complète, modulaire et explicable, qui couvre l'ensemble de la chaîne environnementale de Gabès : de la détection de la pollution à la valorisation des déchets, en passant par la santé publique et la compliance industrielle. Son architecture 3-tiers, sa diversité de modèles IA et son approche systématique de l'explicabilité en font un candidat solide pour un déploiement opérationnel en Tunisie et potentiellement dans d'autres régions soumises à des pressions environnementales similaires.
